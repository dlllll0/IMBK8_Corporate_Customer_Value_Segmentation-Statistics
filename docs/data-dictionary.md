# 데이터 입력 형식

실제 데이터와 예시 행은 포함하지 않는다. 아래는 제공된 명세서와 노트북 읽기 코드에서 확인한 입력 계약이다. 원파일 재배포 권한을 부여하는 문서가 아니다.

실제 실행에서는 아래 표의 이름으로 복사할 필요 없이 `run_analysis.py`에 원래 로컬 경로를 전달할 수 있다.

## 입력 파일

| 로컬 이름 | 형식 | 결합 키 |
|---|---|---|
| data/private/corporate_transactions.csv | CP949 CSV | 기준년월(고유키 아님) |
| data/private/monthly_rates.csv | UTF-8 CSV | 기준년월 |
| data/private/estimated_fee_rates.csv | UTF-8 CSV | 연도(year) |

키 형식은 YYYYMM 및 YYYY 정수값이다. 보조 테이블의 키가 유일해야 left join이 원행 수를 늘리지 않는다. 원 수수료 CSV에 완전 빈 행이 있으므로 파일 검사 시 빈 행은 건너뛴다. 계산값이나 원 CSV를 스키마에 채워 넣지 않았다.

## 보조자료와 파생변수

- 금리 파일: `기준년월`, `평균대출금리(%)`, `평균예금금리(%)`, `예대마진(%)`. 가설 노트북의 입력값×0.01 산식을 그대로 사용하며 추가 /12를 하지 않는다. 실제 계약금리가 아닌 보조 평균값이다.
- 수수료 파일: `연도(year)`, `신탁보수율(trust)`, `카드수수료율(card)`, `수익증권/연금(fund)`, `외환/기타(fx)`, `채널건당(channel)`. 비율의 %와 소수 표현을 혼동하지 않는다. 후자는 원/건으로 기술됐으나 원분석에서 채널수익은 합산하지 않는다.
- 총예금잔액: 요구불·거치식·적립식 잔액 합. 총대출잔액: 운전·시설 대출잔액 합. 자산관리잔액: 수익증권·신탁 잔액 합(가설 노트북 기준).
- 코드상 총자산은 버전별 정의가 다르므로 재무제표 총자산으로 해석하지 않는다. 명세서의 파생 열명·단위가 코드와 다른 부분은 비공개 메모에 기록했다.
- `FAI`, `FPI`, `등급`은 입력에 요구하지 않는다. 승인된 입력으로 계산하는 파생 결과이다.

## 스키마만으로 확인할 수 없는 것

실행 결과 원 CSV는 347,299행이다. 스키마만으로 확인할 수 없는 것은 법인 반복관측, 비식별 처리의 충분성, 월별 금액의 집계 방식, 실제 결측과 0의 의미, 공개 허용 범위. 헤더 검사 통과가 데이터 타당성 또는 재현 성공을 뜻하지 않는다.
